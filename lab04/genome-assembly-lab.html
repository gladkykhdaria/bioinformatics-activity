6. How many reads do you really need?

The Lander–Waterman formula predicts how many letters stay unread: G × e−c, where G is the genome length and c = reads × average length ÷ G is the coverage.

How it works, in simple words

  1. Sample the reads

    A window of random length (100–150) lands at a random spot and copies the letters inside. 20,000 times. A real sequencer does the same: it can only read short pieces from random places.

    CS: random sampling

  2. Throw away duplicates

    Identical reads add nothing new, so only one copy is kept.

    CS: set

  3. Index the reads

    Each read is filed under its first 20 letters. To find "which read starts with these letters" the app looks it up directly instead of comparing all 20,000 reads with each other (that would be 400 million comparisons).

    CS: hash table

  4. Grow a contig

    Start from the longest read. Look at the last letters of the contig and find reads whose beginning is exactly the same for at least 30 letters. Glue on the one that adds the most new letters. Repeat until nothing matches, then do the same to the left.

    CS: greedy algorithm, suffix = prefix matching

  5. Handle gaps

    If a part was never read, growth stops there. The app starts a new contig from an unused read, so low coverage gives several pieces instead of one.

    CS: repeat until every read is used

  6. Check

    Compare the rebuilt genome with the original, letter by letter.

    CS: string comparison

Why 30 letters of overlap is safe here: the longest piece that repeats inside this virus is only 12 letters, so a 30-letter overlap can only fit in one place. In genomes with long repeats (like the human genome) this simple method gets confused.

Reads are simulated from one strand, without sequencing errors. Everything runs in your browser.
